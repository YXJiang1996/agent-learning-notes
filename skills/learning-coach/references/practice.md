# 实践、测评和复习

## 最小实验

使用 `assets/experiment.md`，先写问题、假设、环境与版本、输入、预期结果、指标和失败条件，再实现。至少覆盖与问题相关的一条正常路径和一条失败或边界路径；比较时固定输入及条件，说明模型随机性或环境差异。

用户想学习实现时，先让其预测关键行为、解释方案或完成适量代码；用户明确要求直接提供实现时照做，但把辅助程度标为共同完成或 Agent 生成。不要用减少帮助来强迫教学。

只有真实执行的实验才能填写实际结果。未运行的代码标为待验证。结果支持什么、不能支持什么分别说明，最小原型不等于可生产使用。

## 测评

依据计划中的掌握标准选择题型与数量。短测通常 3–5 题，可覆盖概念解释、源码追踪、场景应用、故障推演或需求变化后的设计；不要求每次包含所有题型。

出题时同时确定每道题的考察维度、评分要点和通过条件，以免看过答案再移动标准；不要提前把答案放进可见试卷或仓库。评分依据可暂留当前会话，恢复会话时在读取作答前依据原题重建。仓库文件不提供考试保密性，不声称把答案另存文件就能隐藏。

使用 `assets/assessment.md`：先保存题目与状态“待作答”，等待真实作答，不代填用户答案；作答后保存原文、提示情况、评分依据和逐题反馈。用户要求看答案可以提供，并记录已揭示；该题不再作为独立掌握证据。

评价应说明正确部分、错误原因、薄弱点和下一步练习。部分正确与使用提示分别记录，分数只是辅助，不能直接映射所有掌握维度。

## 五个维度

| 维度 | 足以支持掌握判断的证据示例 |
| --- | --- |
| 概念理解 | 用自己的话正确解释机制、边界及常见误区 |
| 源码追踪 | 在固定版本中独立追踪关键路径并解释状态变化 |
| 设计判断 | 基于需求约束比较方案，说明取舍和失败情况 |
| 独立实现 | 独立完成相关实现或关键改动，并能解释验证结果 |
| 效果验证 | 设计可复现实验、选择合理指标并解释结果限制 |

每个维度状态为未评估、学习中、待验证或已验证。仅真实证据满足该维度的验收条件时标为已验证。`独立实现` 的已验证证据必须包含学习者独立完成的记录；Agent 生成、共同完成或提示下完成的产物本身不足以证明独立实现。

## 复习

根据薄弱点、重要性和可用时间安排复核。后续用新输入、新源码路径或新约束检查迁移，避免重复原题产生记忆假象。到期标为需要复核，不因时间经过自动取消已验证状态；新证据出现矛盾时保留历史，更新当前判断及原因。
