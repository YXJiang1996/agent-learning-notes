# Agent Teams：从产品机制到自己的实现

- 稳定 ID：agent-teams
- 开始日期：2026-09-11
- 主线：Claude Code Agent Teams 的公开机制与可观察行为。
- 演示语言：TypeScript。
- 本轮目标：解释团队任务与消息的运行过程，设计并逐步实现一个支持依赖、任务领取、消息和失败恢复的最小协作运行时。

## 工程问题

1. 哪些任务值得分工，哪些任务并行反而更慢？
2. 一个队友需要哪些上下文，哪些状态由团队共享？
3. 任务、执行者和消息分别如何建模，谁拥有任务？
4. 两个执行者同时领取任务时如何防止重复执行？
5. 执行者沉默时，如何区分空闲、阻塞和崩溃？
6. 取消、重试、重复消息和迟到结果如何处理？
7. 共享任务状态是否意味着共享文件安全，工作区隔离如何配合？
8. 如何比较单 Agent、中心式子 Agent 和团队协作的效果与开销？

## 前置与范围

按需补齐 Agent 工具调用循环、上下文隔离、Promise 与事件循环、状态机、原子更新、消息关联及幂等性。已有基础先诊断，不重复安排整套语言课程。

第一轮不实现容器隔离、多机器部署、复杂长期记忆或完整产品界面。它们属于后续扩展。

## 掌握标准

| 维度 | 本轮验收 |
| --- | --- |
| 概念理解 | 区分模型、Agent 执行实例、任务和消息；解释并行的收益与代价 |
| 源码追踪 | 在固定提交的开源 TS 实现中追踪委派、上下文传递和返回路径 |
| 设计判断 | 按同一需求比较团队协作与中心式子 Agent，并说明版本与证据边界 |
| 独立实现 | 独立完成原型中的关键状态转换，解释并测试重复领取或失败恢复 |
| 效果验证 | 在固定任务上比较完成质量、耗时、模型调用开销及故障表现 |

Claude Code 的内部源码尚未取得或验证。本轮不把产品文档当成内部源码，也不将自制 TS 原型称为其真实实现。
